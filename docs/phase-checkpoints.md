# 四阶段与脉冲卡片

复杂任务在阶段进入和结束时输出短卡片；发生实际阻塞、验收变化或迭代熔断时及时更新。卡片内容以文件、退出码、审查记录和实际结果为依据。没有新证据时不宣称新进展，不靠卡片数量证明工作量。

| 阶段 | 完成条件 | 给用户的证据 |
|---|---|---|
| Phase 1: 资产摸底与约束冻结 | 已阅读规则、最新会话和相关资产；任务目标、支持范围、不做事项和验收命令明确 | 任务文档及相关资产位置 |
| Phase 2: 核心实施与测试 | 范围内实施完成，真实验收命令退出0 | 修改摘要、测试命令、退出码与日志 |
| Phase 3: 异构独立审查 | 获得有效 APPROVED 或 APPROVED_WITH_NOTES；否则修复已核验问题或交用户裁决 | 原始报告、问题裁定、迭代计数与争议报告 |
| Phase 4: 交付归档与提交 | 已整理交付证据并按用户授权归档和提交 | 交付路径、建议清单、已执行的同步/提交结果 |

最小卡片格式：

```text
[Phase 2: 核心实施与测试] 完成
完成：实现范围内变更。
证据：验收命令、退出码0、日志路径。
下一步：独立审查。
阻塞：无（有阻塞时说明具体原因和所需决定）。
```

同一阶段的修复复测属于该阶段内的工作，不能为每次修改另起生命周期或清空审查计数。批准后的建议可以归档给用户，不自动开启实施任务。提交、同步和外部发布按已有用户授权执行；卡片本身不创造新的授权。
