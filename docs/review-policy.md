# 审查与收工规则

## 第1版：固定验收标准

开工前明确目标、可验证的验收标准、支持范围、不做事项和验收命令。未确认的假设不作为强制验收要求。

规划入口要求输出这些项目。审查入口默认读取目标工程的 `docs/task.md`，也接受显式 `--task`。显式文件缺失、为空或编码错误时停止；未提供文档时遵循用户明确指令与既有功能保证。

任务内容按 SHA-256 快照传入审查。审查期间任务文档变化，本次批准失效。审查不能自行扩大范围；可选命名调整、重构和未来功能不变成强制任务。相关安全、数据完整性和已有功能回归仍属审查范围。

快照通过 CLI 支持的 stdin 提示词传递，避免长文档超过 Windows 命令行长度限制。默认文档从缺失变为出现也会使本次批准失效；带 UTF-8 BOM 的空文档按空文件处理。

## 第2版：问题必须有证据

每个必须修复的发现记录唯一稳定 ID、位置、支持范围内的具体触发条件、预期行为、实际行为、影响和证据。证据可为实际复现，或确定、可达的代码路径；偏好和未来假设不构成已核验缺陷。

结果协议升级为 `codex-loop-review-v2`，包含与原生发现一一对应的证据记录。缺少字段、未经核验、ID 重复或数量不一致时，保持待审查，不能直接派发修改。只说整体错误却没有具体缺陷证据，也不产生返工指令。包装器验证证据契约，实际证据的真实性仍由审查器核对代码和测试。

证据记录复制原生标题及绝对路径、行号范围。包装器核对 CLI 0.159.2 附加的问题列表；多出、缺失或替换条目均不产生修复判定。未知渲染格式保持待审查，不猜测其含义。
